## 2. 当前明确未完成：家长看不到学生评价

### 现象

当前 Pilot 中，家长登录后不能正常看到学生的完整评价内容。

这属于**未完成业务能力 / 产品缺口**，不能把“家长账号可以登录”或“存在 GuardianRelationship”误判为“家长报告查看流程已经完成”。

### 下一步需要检查

需要沿完整链路核查：

```text
Subject Teacher 写入评价
→ 学科评价提交
→ Homeroom 审核
→ Academic Admin 发布
→ GuardianRelationship 解析
→ Guardian 查询已发布报告
→ report_content_for() / subject_comment_content_for()
→ 家长端模板显示完整家长可见内容
```

必须验证：

- 家长只能看到与自己存在有效 GuardianRelationship 的学生；
- 只有 `PUBLISHED` 报告可见；
- 家长能看到所有明确标记为家长可见的学科评价；
- `staff_note` 等内部字段永远不能泄露给家长；
- 学生视图与家长视图仍保持不同可见范围；
- 家长入口在 Dashboard 中足够明显，不依赖猜测 URL；
- 至少增加浏览器 / View 层测试覆盖真实 guardian 登录场景。

在此问题修复前，不应把“家长查看报告”标记为产品完成。

## 3. 新的强制学生身份显示要求：姓名 + 性别

### 产品要求

从下一阶段开始，学生模拟数据和后续正式学生模型 / UI 必须满足：

> **任何需要老师、家长、AI 或管理人员理解“当前正在处理哪一个学生”的核心页面，都应明确显示学生姓名和性别。**

姓名不能只藏在内部对象或某个详情页中；性别也不能只存在数据库而不显示。

至少在以下教师核心上下文中持续可见：

- 教师连续录入工作区；
- 单学生评价页；
- 批量导入预检；
- 班主任审核；
- 报告详情；
- AI 辅助润色 / 语法纠错预览。

### 数据字段原则

当前 `Student.full_name` 已承担姓名来源。下一步应新增明确的结构化性别字段，不能让 AI 从姓名猜性别。

建议模型语义：

```text
gender = MALE | FEMALE | UNSPECIFIED
```

其中：

- `MALE`：英文默认人称代词映射到 he / him / his；
- `FEMALE`：英文默认人称代词映射到 she / her / hers；
- `UNSPECIFIED`：字段未完成，不允许 AI 自行根据姓名推断 he / she。

UI 即使遇到 `UNSPECIFIED`，也应明确显示“未设置”，而不是把字段悄悄隐藏。

### 为什么它是核心结构字段，而不是 UI 装饰

该字段未来会直接参与英文 AI 辅助流程，例如教师原始评价：

```text
Mika has improved a lot. He can now explain loops clearly.
```

系统向 AI 提供结构化上下文：

```text
Student name: Mika Chen
Gender: FEMALE
```

AI 可以在不改变教育事实的前提下完成：

```text
Mika has improved a lot. She can now explain loops clearly.
```

因此后续 AI 设计必须遵守：

```text
教师原始事实
+ Student.full_name
+ Student.gender
→ AI grammar / wording assistance
→ 候选修改
→ 人工确认
→ 现有 Report Service
```

### 严格约束

- AI **不得通过姓名猜性别**；
- AI **不得因为语法纠错而改变教师表达的教育事实**；
- 性别字段来自学校正式学生资料或受控模拟数据；
- AI 输出仍然只是候选文本，不直接获得提交或发布权限；
- 姓名与性别应作为 AI 上下文中的稳定结构字段，而不是让模型从自由文本重新抽取。

## 4. 下一阶段优先级

下一阶段恢复开发时，优先顺序应为：

1. 修复并完整验证家长查看已发布学生评价；
2. 为 Student 增加结构化 `gender` 字段及迁移；
3. 更新 18 人 Pilot 数据，为每名学生设置明确姓名和性别；
4. 在教师连续录入、审核、家长报告等核心界面持续显示姓名 + 性别；
5. 增加权限和展示测试；
6. 在上述基础稳定后，再接 AI 文本润色 / 性别代词纠错；
7. 最后再进入真正的语音识别与自然语言结构化输入。

不要倒序先做语音。否则会出现 AI 能听懂老师讲话，却连评价最终该给哪个人、该显示 he 还是 she 都没有可靠结构字段的荒唐局面。

## 5. 当前产品判断

Phase 7 已证明教师高吞吐录入方向成立，但当前 Pilot 仍远未达到“报告业务闭环完成”。

当前更准确的状态是：

```text
教师高效录入：已形成可测试版本
批量导入：已形成可测试版本
报告审核 / 发布：已有基础状态机
家长最终查看：存在明确缺口
学生身份展示：需要补充性别结构字段
AI 辅助文本：只有架构边界，尚未正式实现
语音输入：只有设计约束，尚未实现
```

因此后续开发必须继续坚持：先补真实业务闭环，再扩 AI 输入能力。
