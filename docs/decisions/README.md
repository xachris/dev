# Architecture Decision Records（ADR）

本目录记录已经经过讨论、实现或验证的重要架构决定。

这些文档不是“永远不能改”的圣旨，而是为了防止后续开发者、供应商或 AI 模型在不了解历史背景和业务权衡的情况下，凭个人偏好直接推翻已有设计。

## 接手规则

在修改以下类型的基础决策之前，必须先阅读相关 ADR：

- 前端技术栈；
- 后端框架；
- 数据库；
- 身份与权限架构；
- 多租户方式；
- 状态机；
- 核心部署拓扑；
- 是否拆微服务；
- AI / 邮件等外部能力边界。

如果要推翻一个 `Accepted` ADR，应新增一个 ADR 说明：

1. 原决定当时为什么合理；
2. 哪个现实条件已经变化；
3. 新方案解决了什么已被验证的问题；
4. 迁移成本和风险；
5. 如何保持权限、安全和业务语义不退化；
6. 如何验证新方案确实更好；
7. 如何回滚。

不得仅以“更现代”“更主流”“模型更喜欢”“行业都这么做”等理由替换已经运行和验证的架构。
