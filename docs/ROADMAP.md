# 平台级开发路线图

本文档描述学校数字化平台的战略版本路线。具体施工顺序、交付物和验收条件以 [`DEVELOPMENT_PLAN.md`](DEVELOPMENT_PLAN.md) 为准。

## 总体方向

平台定位不是“再造一个功能更多的 SIS”，而是建立一套现代学校运营基础设施：

```text
Identity
+ Relationship
+ Permission
+ Event
+ State
+ Workflow
+ Timeline
+ Action
```

在这套底层能力上逐步组合学校业务，而不是不断增加彼此割裂的模块。

核心目标：

- 少录入
- 少重复
- 少等待
- 少错误
- 少人工协调
- 更多自动化
- 更高业务质量
- 更清晰的学生持续数据

---

## V0.1：平台底座 + 学习报告闭环

### 目标

仅使用虚拟数据，完成平台最小基础设施，并跑通第一个完整业务闭环。

### 平台底座

- Django + PostgreSQL 工程
- 多学校 / 多租户基础
- Student ID
- User / Student / Guardian / Staff 身份
- 角色与关系权限
- AcademicYear / Class / Subject / TeachingAssignment
- Event 基础层
- Student Timeline 第一版
- Audit 基础

### 首个业务闭环

```text
教师填写
→ 提交
→ 班主任审核
→ 批准
→ 发布
→ 家长查看 / 学生查看
```

### 验收重点

不是“页面能打开”，而是：

- 跨学校数据隔离正确
- 学生 / 家长 / 教师权限正确
- 内容可见级别正确
- 状态非法跳转被拒绝
- 教师批量填写效率可接受
- 班主任能优先处理异常
- 所有关键动作可追踪

---

## V0.2：通知、部署与真实运行准备

### 目标

让核心闭环具备接近真实学校运行的工程条件。

### 能力

- Notification Outbox
- 测试邮件适配器
- Outlook / SMTP 适配器
- 失败重试与防重复发送
- Staging 环境
- Linux + PostgreSQL + Nginx + HTTPS
- 自动备份与恢复
- 基础监控
- 安全加固
- 权限回归测试

---

## V0.3：AI 辅助层

### 目标

在不改变教育责任和权限边界的前提下，让 AI 减少文字与信息处理工作。

### 第一批 AI 能力

- 中文评价润色
- 重复表达检查
- 内容完整性提醒
- 报告汇总草稿
- 长期学习反馈摘要

### 原则

系统必须在：

```text
AI_PROVIDER=none
```

时完整运行。

AI 不得推断身份、收件人、家长关系或编造教育事实。

---

## V0.4：有限生产试点

### 目标

以真实业务结果验证产品，而不是以功能完成数量判断成功。

### 试点范围

- 少量班级
- 少量教师
- 一个报告周期

### 核心指标

- 教师平均填写时间
- 每名学生平均操作次数
- 班主任平均审核时间
- 重复录入次数
- 报告返工率
- 家长查看成功率
- 支持请求数量
- 错误率

只有业务效率明显改善，才扩大范围。

---

## V0.5：统一请假 + 出勤

学习报告稳定以后，优先评估高频且重复劳动严重的流程。

### 目标

不做两个孤立模块，而是建立统一状态链：

```text
LeaveRequested
→ LeaveApproved
→ ExpectedAttendance Changed
→ Attendance Exception Detection
→ Human Handles Exception Only
```

目标不是“拥有考勤数据”，而是减少教师机械点名和重复确认。

---

## V0.6：Schedule / Timetable 基础

### 第一阶段定位

课表首先是整个系统的状态来源：

> 谁，在什么时间，应该在哪里，与谁发生什么教学活动。

### 后续逐步增加

- 冲突检测
- 教室分配
- 调课影响自动传播
- 替课建议
- 更少人工排课干预

是否增加自动排课算法，由真实需求和收益决定。

---

## V0.7：Assignments / Learning Tasks

### 目标

不是复制大型 LMS，而是形成连续学习数据链：

```text
任务发布
→ 学生提交
→ 教师反馈
→ Learning Record
→ Student Timeline
→ Report
```

避免教师在作业系统写一次反馈，到了报告期又重新写一遍。

---

## V0.8：家长行动中心

### 目标

减少消息噪声，把真正需要家长处理的事项集中成 Action。

可能包括：

- 待确认通知
- 待审批 / 待填写表单
- 学习报告
- 请假状态
- 家长会安排
- 需要回应的学校事项

重点不是增加沟通渠道，而是减少家长寻找信息和判断“我现在到底要做什么”的成本。

---

## V1.0：现代学校核心运营平台

达到 V1.0 不以模块数量判断，而以以下条件判断：

- 多学校可以稳定运行
- 核心身份和权限体系成熟
- 学生关键事件形成连续 Timeline
- 学习报告稳定运行
- 至少一个高频行政流程实现明显自动化
- 重复录入显著下降
- 教师与行政人员人工操作时间有真实测量改善
- 系统具备备份、恢复、安全、审计和标准部署能力
- 新模块可以复用统一底层能力，而不需要重新造孤岛

# 长期扩展原则

未来可以继续扩展：

- 招生
- Assessment
- Behaviour / Pastoral
- 家长会
- 校车
- 宿舍
- 文件 / 表单
- 财务接口
- 第三方 SIS / LMS 集成
- 数据分析
- AI Agent

但任何模块都必须先通过 `PRODUCT_PHILOSOPHY.md` 的检查。

传统软件“别人有，所以我们也要有”不能作为立项理由。
